# TV Remote Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Kotlin Android app that replaces the LG Magic Remote on Ponds' Pixel, including power-on.

**Architecture:** One Compose screen talks to a `TvController`, which wraps an SSAP WebSocket client
(`SsapClient`), the TV's pointer socket (`PointerSocket`) for D-pad buttons, and a Wake-on-LAN sender
(`Waker`). A ViewModel owns the connection state machine. Settings live in DataStore.

**Tech Stack:** Kotlin, Jetpack Compose (Material 3, Compose BOM), OkHttp 4.12 (WebSocket +
MockWebServer for tests), kotlinx.serialization JSON, kotlinx.coroutines, DataStore Preferences,
JUnit 4. Gradle wrapper, AGP = newest stable that supports compileSdk 36 on JDK 21.

**Spec:** `docs/superpowers/specs/2026-11-05-tv-remote-design.md`

## Global Constraints

- Package `com.ponds.tvremote`; minSdk 31; compileSdk/targetSdk 36 (installed: platforms android-36, build-tools 36.0.0, JDK 21).
- Defaults: TV IP `192.168.1.50`, TV MAC `00:11:22:33:44:55`; both editable in Settings.
- SSAP: try `wss://<ip>:3001` first, fall back to `ws://<ip>:3000`.
- Wake-on-LAN: magic packet = 6×`0xFF` + 16×MAC, sent to `255.255.255.255`, the /24 broadcast of the TV IP, and the TV IP itself, on UDP ports 9 and 7.
- Power-on wait: poll power state every 1 s, give up after 15 s.
- Reconnect backoff: 1, 2, 4, 8, 10, 10… s, only while the app is in the foreground.
- Self-signed cert: pin SHA-256 of the TV cert on first successful connect; trust only that cert for the saved IP.
- Permissions in the manifest: `INTERNET`, `ACCESS_NETWORK_STATE`, `VIBRATE`.
- **No git commits unless Ponds asks** (his working rule). Each task ends with a test run instead. `git init` once in Task 1 is fine so diffs can be reviewed.
- UI text is plain and short, no "AI" anywhere.

## Review Focus

1. **TV in standby still answers on the network.** Connected ≠ on. Power button must use `getPowerState`, never "is the socket open". Test in Task 5.
2. **Pairing prompt ignored or declined.** TV sends `error` (or nothing for ~60 s). App must show "Pairing was declined. Try again." and not loop prompts. Test in Task 3.
3. **TV cert changes** (firmware update). Pin mismatch must show "The TV's certificate changed. Forget pairing in Settings." not silently trust it. Test in Task 3.
4. **App goes to background mid-session.** Sockets close; on return it reconnects once without stacking duplicate connections. Test in Task 6.
5. **Holding a phone volume key.** Key repeats send one `VOLUMEUP` each; no crash or queue explosion when the socket is down (buttons just no-op while not connected). Test in Task 6.

### Task 3: SsapClient + TLS pin + pairing

**Files:** Create `tv/Ssap.kt`, `tv/Registration.kt`, `tv/TlsPin.kt`; Test `test/.../tv/SsapClientTest.kt`, `test/.../tv/TlsPinTest.kt`

**Interfaces:**
- Produces:
  - `sealed interface PairResult { data class Paired(val clientKey: String): PairResult; object Declined: PairResult; data class CertChanged(val newPin: String): PairResult; data class Unreachable(val cause: Throwable): PairResult }`
  - `class SsapClient(http: OkHttpClient)` with
    `suspend fun connect(url: String, clientKey: String?): PairResult`,
    `suspend fun request(uri: String, payload: JsonObject = JsonObject(emptyMap())): JsonObject` (returns the `payload` of the matching `response`; throws `SsapError(message)` on `type:"error"`; 5 s timeout),
    `fun close()`, `val isOpen: Boolean`.
  - `class TlsPin(pinnedSha256: String?)` exposing `fun okHttp(base: OkHttpClient): OkHttpClient` and `var seenPin: String?` (SHA-256 hex of the leaf cert, set during handshake).
  - `fun pinFor(cert: X509Certificate): String` (lower-case hex SHA-256 of `cert.encoded`).
- `Registration.kt`: `fun registerPayload(clientKey: String?): JsonObject`. Copy the **signed** manifest from bscpylgtv's source (`pip download bscpylgtv --no-deps`, read it, MIT) so webOS 23 grants the permissions; it must include `READ_POWER_STATE`, `CONTROL_POWER`, `CONTROL_AUDIO`, `CONTROL_INPUT_MEDIA_PLAYBACK`, `READ_INPUT_DEVICE_LIST`, `CONTROL_INPUT_TV`. Add `"client-key"` only when not null; `"pairingType": "PROMPT"`.

Protocol facts the implementer needs:
- Send `{"type":"register","id":"reg0","payload":<registerPayload>}`.
- TV replies `response` with `pairingType: PROMPT` (waiting on the TV), then `registered` with `payload["client-key"]`, or `error` if declined. Wait up to 60 s for `registered`.
- Requests: `{"type":"request","id":"<n>","uri":"ssap://…","payload":{…}}`; match replies by `id`.

- [ ] **Step 1: Write failing tests** with `MockWebServer` + `withWebSocketUpgrade` scripting the TV:

```kotlin

@Test fun sendsSavedClientKey()           // connect(url,"abc") → first frame's payload["client-key"] == "abc"
@Test fun declinedPairing()               // server replies error → Declined
@Test fun requestMatchesById()            // server answers id "2" before id "1" → each request() gets its own payload
@Test fun requestErrorThrows()            // type:"error" → SsapError with the error text
@Test fun requestTimesOut()               // no reply → throws within 5 s (use virtual time or a short injectable timeout)
@Test fun unreachable()                   // url to a closed port → Unreachable
```
`TlsPinTest`: `HeldCertificate` A, server with A:
```kotlin

@Test fun matchingPinConnects()           // TlsPin(pinFor(A)) → OK
@Test fun changedCertIsRejected()         // TlsPin(pinFor(B)) against A → handshake fails, seenPin == pinFor(A)
```

### Task 6: RemoteViewModel (connection state machine)

**Files:** Create `ui/RemoteViewModel.kt`; Test `test/.../ui/RemoteViewModelTest.kt` (kotlinx-coroutines-test, virtual time)

**Interfaces:**
- Consumes: `Tv`, `Prefs`, a `connect: suspend (Settings) -> PairResult` lambda (wraps `SsapClient.connect` with wss→ws fallback and opens the pointer socket).
- Produces:
  - `sealed interface Status { object Connecting; object On; object Off; object Pairing; object Declined; object CertChanged; object Unreachable }` (shown by the chip: "Connecting…", "Connected", "TV off", "Press OK on the TV to allow this phone", "Pairing was declined. Try again.", "The TV's certificate changed. Forget pairing in Settings.", "Can't reach the TV. Are you on home Wi-Fi?")
  - `class RemoteViewModel(...) : ViewModel { val status: StateFlow<Status>; val inputs: StateFlow<List<Input>>; fun onForeground(); fun onBackground(); fun power(); fun press(b: Button); fun playPause(); fun loadInputs(); fun setInput(id: String); fun retry() }`
- Rules: `onForeground` starts one connect loop (a second call while running does nothing). `onBackground` cancels it and closes sockets. Backoff 1,2,4,8,10 s. On `Paired` save `clientKey` and the seen pin. `power()`: if `isOn()` → `powerOff()`; else `wake()`, then poll `isOn()` each 1 s for 15 s, status `On` when true, else stays `Off`. `press` while not `On` does nothing. `playPause` alternates `play()`/`pause()` starting with `pause()`.

```kotlin
@Test fun certChangedShowsMessage()          // → status CertChanged, no reconnect  (RF 3)
@Test fun backoffDelays()                    // Unreachable ×4 → connect at t=0,1,3,7 s
@Test fun foregroundTwiceOneLoop()           // onForeground() twice → one connect in flight  (RF 4)
@Test fun backgroundStopsLoop()              // onBackground() → no more connect calls
```
